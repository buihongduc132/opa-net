## Fix 1 (v1): Drop spoofable OPA_GATE_INTERNAL guard (Critical)

- **Issue**: Inheritable `OPA_GATE_INTERNAL=1` allowed callers to bypass shim interception and policy evaluation completely (`OPA_GATE_INTERNAL=1 /opt/opa-gate/bin/git checkout feature-evil` passed through directly to real git).
- **Changes**:
  - Removed recursion guard check, `export OPA_GATE_INTERNAL=1`, and `unset OPA_GATE_INTERNAL` from `scripts/.opa-gate-shim`.
  - Removed `export OPA_GATE_INTERNAL=1` from `scripts/opa-gate-audit-append`.
  - Deployed updated shim and audit-append to `/opt/opa-gate/scripts/` and `/opt/opa-gate/bin/.opa-gate-shim`.
  - Added unit tests in `tests/unit/shim/opaGateShim.test.ts`.
- **Evidence**:
  - RED before: `OPA_GATE_INTERNAL=1 /opt/opa-gate/bin/git checkout feature-evil` returned exit 1 (`error: pathspec 'feature-evil' did not match any file(s) known to git`), bypassing opa-gate without audit entry.
  - GREEN after: `OPA_GATE_INTERNAL=1 /opt/opa-gate/bin/git checkout feature-evil` returns exit 2 (`BLOCKED: git checkout feature-evil (rule: custom:761ff53e)`), with `audit.jsonl` entry source `opa`.

## Fix 3 (v3): Block git branch -m/--move in protected worktrees (High)

- **Issue**: `git branch -m <name>` renames the current branch in place without checking out or switching, silently evading branch allowlist in protected repos/worktrees.
- **Changes**:
  - `policy/safety.rego`: added deny rule blocking `git branch -m` and `git branch --move` when `repo_available_protected` is true.
  - `src/rules/catalog.ts`: registered rule `block-git-branch-move-protected`.
  - `tests/e2e/bypass-fixes.test.ts`: added tests covering `-m` deny in protected worktrees, `--move` deny, and allow when `PIOPANET_PROTECT_DAYS=0`.
- **Evidence**:
  - RED before: `pi-opa-net eval 'git branch -m feature-evil' --json` returned `{"decision":"allow"}` in protected repo.
  - GREEN after: `pi-opa-net eval 'git branch -m feature-evil' --json` returns exit 2 (`BLOCKED: git branch -m feature-evil (rule: block-git-branch-move-protected)`). Non-protected worktree (`PIOPANET_PROTECT_DAYS=0`) retains `allow`.

## Fix 4 (v5): Treat @ as HEAD in symbolic-ref and update-ref (Medium)

- **Issue**: `git symbolic-ref @ refs/heads/feature-evil` and `git update-ref @ <sha>` used `@` as the HEAD shorthand to bypass the literal `"HEAD"` check in `symbolic_ref_mutates_head` and `update_ref_targets_branch`.
- **Changes**:
  - `policy/safety.rego`: added `is_head_ref(arg)` helper matching `"HEAD"` and `"@"`. Used `is_head_ref` in `symbolic_ref_mutates_head` guards and `not is_head_ref(other)` exclusion. Added `refs/heads/` boundary and `is_head_ref(arg)` in `update_ref_targets_branch`.
  - `tests/e2e/bypass-fixes.test.ts`: added tests covering `@` mutation deny, `@` read query allow, `--short @` allow, and `update-ref @` deny.
- **Evidence**:
  - RED before: `pi-opa-net eval 'git symbolic-ref @ refs/heads/feature-evil' --json` returned `{"decision":"allow"}` in protected repo.
  - GREEN after: `pi-opa-net eval 'git symbolic-ref @ refs/heads/feature-evil' --json` returns exit 2 (`BLOCKED: git symbolic-ref @ refs/heads/feature-evil (rule: block-git-symbolic-ref-head)`). Read queries (`git symbolic-ref @` and `git symbolic-ref --short @`) remain allowed (exit 0). `git update-ref @ <sha>` returns exit 2 (`BLOCKED: ... (rule: block-git-update-ref-branch)`).

## Fix 5 (v6): Block git update-ref --stdin in protected worktrees (Medium)

- **Issue**: `git update-ref --stdin` (e.g. `printf 'update refs/heads/main ...\n' | git update-ref --stdin`) allows blind ref updates from stdin without passing refs as argv arguments, evading argv inspection.
- **Changes**:
  - `policy/safety.rego`: added deny rule blocking `input.subcommand == "update-ref"` when `has_any_arg(input.args, ["--stdin"])` and `repo_available_protected` is true.
  - `src/rules/catalog.ts`: registered rule `block-git-update-ref-stdin`.
  - `tests/e2e/bypass-fixes.test.ts`: added tests covering direct `git update-ref --stdin`, piped `printf | git update-ref --stdin`, and allow in non-protected worktrees.
- **Evidence**:
  - RED before: `pi-opa-net eval 'git update-ref --stdin' --json` returned `{"decision":"allow"}` in protected repo.
  - GREEN after: `pi-opa-net eval 'git update-ref --stdin' --json` returns exit 2 (`BLOCKED: git update-ref --stdin (rule: block-git-update-ref-stdin)`). Piped form `printf '...' | git update-ref --stdin` returns exit 2 (`BLOCKED`). Non-protected worktree (`PIOPANET_PROTECT_DAYS=0`) retains `allow`.
