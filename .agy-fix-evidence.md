## Fix 4 (v5): Treat @ as HEAD in symbolic-ref and update-ref (Medium)

- **Issue**: `git symbolic-ref @ refs/heads/feature-evil` and `git update-ref @ <sha>` used `@` as the HEAD shorthand to bypass the literal `"HEAD"` check in `symbolic_ref_mutates_head` and `update_ref_targets_branch`.
- **Changes**:
  - `policy/safety.rego`: added `is_head_ref(arg)` helper matching `"HEAD"` and `"@"`. Used `is_head_ref` in `symbolic_ref_mutates_head` guards and `not is_head_ref(other)` exclusion. Added `refs/heads/` boundary and `is_head_ref(arg)` in `update_ref_targets_branch`.
  - `tests/e2e/bypass-fixes.test.ts`: added tests covering `@` mutation deny, `@` read query allow, `--short @` allow, and `update-ref @` deny.
- **Evidence**:
  - RED before: `pi-opa-net eval 'git symbolic-ref @ refs/heads/feature-evil' --json` returned `{"decision":"allow"}` in protected repo.
  - GREEN after: `pi-opa-net eval 'git symbolic-ref @ refs/heads/feature-evil' --json` returns exit 2 (`BLOCKED: git symbolic-ref @ refs/heads/feature-evil (rule: block-git-symbolic-ref-head)`). Read queries (`git symbolic-ref @` and `git symbolic-ref --short @`) remain allowed (exit 0). `git update-ref @ <sha>` returns exit 2 (`BLOCKED: ... (rule: block-git-update-ref-branch)`).

## Fix 5 (v6): Block git update-ref --stdin in protected worktrees (Medium)

  - `tests/e2e/bypass-fixes.test.ts`: added tests covering direct `git update-ref --stdin`, piped `printf | git update-ref --stdin`, and allow in non-protected worktrees.
- **Evidence**:

  - GREEN after: `pi-opa-net eval 'git update-ref --stdin' --json` returns exit 2 (`BLOCKED: git update-ref --stdin (rule: block-git-update-ref-stdin)`). Piped form `printf '...' | git update-ref --stdin` returns exit 2 (`BLOCKED`). Non-protected worktree (`PIOPANET_PROTECT_DAYS=0`) retains `allow`.
